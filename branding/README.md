# OpenQOS branding assets

Original artwork that constitutes the OpenQOS visual identity. Nothing in this
directory may be copied from another distribution.

as the asset generator is `GPL-3.0-or-later`. A font created for this project would be
`OFL-1.1`.

This license governs **copying and adapting the files**. It does **not** grant the
right to use the OpenQOS name or logo as a brand for someone else's product — marks

[licensing.md §5](../docs/licensing.md#5-branding-and-trademark-policy-separate-track).

The artwork licence is still a *proposed* decision, not a settled one; see
[licensing.md §7](../docs/licensing.md).

## Provenance is mandatory

Every asset must be accompanied by a record of the author, the licence, and — if it
was not created specifically for OpenQOS — where it came from.

Assets with non-commercial terms, unclear origin, or terms incompatible with
redistribution cannot be accepted. A single unlicensed wallpaper makes the whole image
undistributable, so this is checked before merge.

[`PROVENANCE.md`](PROVENANCE.md) records it for everything in this directory. It is one
file rather than one per subdirectory because the answer is the same for all of it —
original work by this project — and a per-directory copy would be the same paragraph
repeated four times, which is how claims drift out of sync.

## Contents

| Directory | Contents |
| --- | --- |
| `logo/` | The mark and the horizontal lockup, each in a light-background and a dark-background version. Source of truth for everything else that draws the mark. |
| `wallpapers/` | The default wallpaper, its `metadata.json`, and the raster sizes Plasma loads. |
| `themes/` | KDE Plasma colour scheme. |
| `plymouth/` | Boot splash theme. |
| `tools/` | `render-assets.py`, which renders the raster assets from the SVG sources. |
| `icons/` | **Generated.** The hicolor icon named by `LOGO=openqos-logo` in the os-release file. Written by the generator; edit the mark instead. |
| `logo/dist/`, `wallpapers/contents/` | **Generated.** Review copies and the files the package installs. |

## How this becomes an image

Milestone 7 turns these assets into the `openqos-branding` package
(`packages/openqos-branding`), which installs:

| Installed path | From |
| --- | --- |
| `/usr/share/wallpapers/OpenQOS/` | `wallpapers/` |
| `/usr/share/color-schemes/OpenQOS.colors` | `themes/` |
| `/usr/share/plymouth/themes/openqos/` | `plymouth/` |
| `/usr/share/icons/hicolor/*/apps/openqos-logo.*` | `icons/` |
| `/usr/share/licenses/openqos-branding/` | `PROVENANCE.md` |

The Plasma look-and-feel package that selects the wallpaper and colour scheme lives in
[`config/common/`](../config/common) instead, because it is configuration rather than
artwork — the same reason it is applied per-profile and the artwork is not.

## Technical requirements

These come from where the assets have to end up, and are the reason a "nice image" is
not automatically a usable branding asset:

* **Boot loader and installer** need small raster logos at fixed sizes, in specific
  formats. Vector-only assets are not enough on their own.
* **Plymouth** loads its images by hard-coded filename from the theme's `ImageDir`
  (`watermark.png`, `background.png`, …), so the file has to be named for the module,
  not for us.
* **Plasma** colour schemes are `.colors` files, and a wallpaper is a directory
  (`metadata.json` plus `contents/images/<width>x<height>.<ext>`), not a loose image.
* **The login screen is not SDDM.** Plasma 6.7 replaced SDDM with
  `plasma-login-manager` (`plasmalogin.service`), so there is no SDDM theme to write.
  Theming it is still open work.
* **Keep source and output separate.** The SVGs are maintained; the exported bitmaps
  are build output, regenerated by `tools/render-assets.py`.
